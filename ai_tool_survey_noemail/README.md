# AI Tool Request & Assessment Form — เวอร์ชันไม่ส่งอีเมล (No-Email Build)

ชุดนี้เป็น**สำเนาแยกอีกชุดหนึ่ง** ของระบบเดิม ต่างกันแค่จุดเดียว: **ระบบไม่ส่งอีเมลขออนุมัติเองเลย**

เก็บ log ครบทุกคอลัมน์เหมือนเดิมทั้งหมด แล้วเพิ่มเครื่องมือในหน้า Admin ให้คุณ**รวบรวมรายชื่อที่ต้องส่งขออนุมัติ** ได้ในไม่กี่คลิก จากนั้นคุณส่งอีเมลเองจาก Outlook ของคุณ — ซึ่งเป็นอีเมลภายใน banpu.co.th จึงไม่มีปัญหาตกโฟลเดอร์ Junk เหมือนตอนส่งจาก Gmail

ชุดนี้**ติดตั้งแยกกันคนละที่กับของเดิม** ไม่กระทบระบบที่ใช้งานอยู่เลย

---

## ต่างจากชุดเดิมอย่างไร

| | ชุดเดิม (มีอีเมล) | ชุดนี้ (ไม่มีอีเมล) |
|---|---|---|
| ส่งอีเมลหาหัวหน้าอัตโนมัติ | ✅ ส่ง | ❌ ไม่ส่ง |
| สิทธิ์ที่ Google ขอ | รวมสิทธิ์ส่งอีเมลแทนคุณ | **ไม่ขอสิทธิ์อีเมลเลย** |
| ต้องตั้งทริกเกอร์เวลา | ✅ ต้องตั้ง (ทุก 1 นาที) | ❌ ไม่ต้อง |
| Log ในชีต | ครบ | **ครบเหมือนกันทุกคอลัมน์** |
| ลิงก์อนุมัติที่กดแล้วอัปเดตระบบ | มี (ส่งไปในอีเมล) | **มี** (หน้า Admin ให้คุณคัดลอกไปแปะเอง) |
| เครื่องมือรวบรวมรายชื่อที่ต้องส่ง | ไม่มี | **มี** |

ตรรกะการประเมินทั้งหมดเหมือนกันเป๊ะ — ระดับความลับ, AI Level, การสลับเครื่องมือฝั่ง Claude เป็น Copilot Cowork เมื่อข้อมูลเป็นความลับ, กฎว่าเมื่อไหร่ต้องขออนุมัติ และการคำนวณซ้ำที่ฝั่งเซิร์ฟเวอร์เพื่อกันการปลอมแปลง

---

## วิธีทำงานประจำวัน

1. พนักงานกรอกฟอร์ม → ข้อมูลลงชีตทันที (ประมาณ 2 วินาที)
2. คุณเปิดหน้า Admin — จะเข้ามาที่แท็บ **📧 ต้องส่งขออนุมัติ** ให้เลย ตัวเลขในกล่องสีเหลืองบอกว่ามีกี่รายการค้าง
3. เลือกวิธีส่งอย่างใดอย่างหนึ่ง:
   - **ส่งทีละคน** — คลิก Request ID เพื่อเปิดรายละเอียด แล้วกด **✉️ เปิด Outlook พร้อมเนื้อหา** (Outlook เปิดขึ้นมาพร้อมผู้รับ หัวเรื่อง เนื้อหา และลิงก์อนุมัติครบ กด Send ได้เลย) หรือกด **📋 คัดลอกข้อความอีเมล** ถ้าอยากแก้ข้อความก่อน
   - **ส่งรวบเดียว** — กด **👥 คัดลอกอีเมลหัวหน้าที่ต้องส่ง** ได้อีเมลหัวหน้าทุกคนคั่นด้วย `;` พร้อมวางในช่อง To ทีเดียว
   - **ทำเป็นตาราง** — กด **⬇ Export รายการที่ต้องส่ง** ได้ไฟล์ CSV เฉพาะรายการค้าง พร้อมคอลัมน์ลิงก์อนุมัติของแต่ละคำขอ เอาไปทำ mail merge หรือส่งต่อให้คนอื่นช่วยส่งได้
4. ส่งแล้วกด **✔ ทำเครื่องหมายว่าส่งแล้ว** — รายการจะหายออกจากแท็บ "ต้องส่งขออนุมัติ" กันส่งซ้ำเวลาทีมช่วยกันทำหลายคน
5. หัวหน้ากดลิงก์ในอีเมลของคุณ → เจอหน้าอนุมัติ กดอนุมัติ/ปฏิเสธ + ใส่หมายเหตุ → **ชีตอัปเดตอัตโนมัติ** ไม่ต้องมาคีย์ตาม

ถ้าหัวหน้าไม่สะดวกกดลิงก์ คุณกดอนุมัติแทนได้จากหน้า Admin เหมือนเดิม

## คอลัมน์ที่เพิ่ม/เปลี่ยนในชีต

ชุดนี้ใช้คอลัมน์ `ApprovalEmailSent` แทน `MailStatus` ของชุดเดิม (คอลัมน์อื่นเหมือนกันหมด):

| ค่า | ความหมาย |
|---|---|
| `not-sent` | ต้องขออนุมัติ แต่ยังไม่มีใครส่งอีเมลแจ้งหัวหน้า ← **นี่คือรายการที่คุณต้องทำ** |
| `sent <เวลา> by admin` | มีคนกดทำเครื่องหมายว่าส่งแล้ว |
| `not-needed` | คำขอที่ไม่ต้องขออนุมัติ (AI Level 1) |

แก้ค่าในชีตด้วยมือก็ได้ ระบบอ่านค่าตรงๆ ไม่มีอะไรซับซ้อน

## ติดตั้ง (แยกจากของเดิมทั้งหมด)

### 1. Google Sheet ใหม่

สร้างสเปรดชีตเปล่าใหม่ ตั้งชื่อให้ต่างจากของเดิม เช่น **AI Tool Requests (No Email)** — อย่าใช้ชีตเดิมร่วมกัน เพราะคอลัมน์ตัวสุดท้ายไม่เหมือนกัน

### 2. วางสคริปต์

ในหน้า Sheet ใหม่ → **ส่วนขยาย (Extensions)** → **Apps Script** → ลบโค้ดตัวอย่างทิ้ง → วางไฟล์ `apps-script/Code.gs` จากโฟลเดอร์นี้ทั้งไฟล์

แก้บรรทัดเดียวในบล็อก SETTINGS:

```js
var ADMIN_PASSWORD = 'ตั้งรหัสผ่านของคุณที่นี่';
```

ควรใช้รหัสผ่าน**คนละตัว**กับของชุดเดิม แล้วกด **บันทึก**

*(แนะนำ)* เลือกฟังก์ชัน `selfTest` → **เรียกใช้** → อนุญาตสิทธิ์ · คราวนี้ Google จะขอแค่สิทธิ์เข้าถึงสเปรดชีต **ไม่ขอสิทธิ์ส่งอีเมล** เพราะโค้ดไม่มีการเรียกใช้บริการอีเมลเลย · จะมีแถวทดสอบ 1 แถวขึ้นในชีต ลบทิ้งได้

### 3. Deploy

**ทำให้ใช้งานได้** → **การทำให้ใช้งานได้รายการใหม่** → เฟือง ⚙️ → **เว็บแอป**

| ช่อง | ต้องเลือก |
|---|---|
| ดำเนินการในฐานะ | **ฉัน** |
| ผู้ที่มีสิทธิ์เข้าถึง | **ทุกคน** |

> ⚠️ ต้องเป็น **"ทุกคน"** เฉยๆ ไม่ใช่ "ทุกคนที่มีบัญชี Google" — เลือกผิดแล้วฟอร์มส่งข้อมูลไม่ได้

คัดลอก **URL ของเว็บแอป** ที่ได้ (จะเป็น URL ใหม่ ไม่เหมือนของชุดเดิม)

### 4. ใส่ URL ใน config.js

```js
API_URL: 'https://script.google.com/macros/s/AKfycb...ตัวใหม่.../exec',
```

### 5. อัปโหลดไฟล์เว็บ

อัปโหลด 9 ไฟล์นี้ไปไว้ใน**โฟลเดอร์ใหม่** บน GitHub เช่น `ai_tool_survey_noemail/` (อย่าทับของเดิม):

```
index.html   admin.html   config.js   app.js   admin.js
api.js       recommendation.js   directory.js   style.css
```

จะได้ลิงก์ใหม่คู่หนึ่ง ใช้งานพร้อมกับชุดเดิมได้:

```
ฟอร์ม  https://<user>.github.io/<repo>/ai_tool_survey_noemail/
Admin  https://<user>.github.io/<repo>/ai_tool_survey_noemail/admin.html
```

`apps-script/` และ `build-apps-script.js` ไม่ต้องอัปโหลด — เป็นต้นฉบับสำหรับคัดลอกไปวางใน Google เท่านั้น

### 6. ทดสอบก่อนใช้จริง

1. กรอกฟอร์มหนึ่งใบให้เข้าเงื่อนไขต้องอนุมัติ (เลือกกิจกรรม Level 3) → ต้องได้ Request ID
2. เปิดชีต → มีแถวใหม่ และ `ApprovalEmailSent` = `not-sent`
3. เปิดหน้า Admin → เห็นรายการนั้นในแท็บ "ต้องส่งขออนุมัติ"
4. กดเปิดรายละเอียด → กด **คัดลอกข้อความอีเมล** → วางในอีเมลดู ต้องมีลิงก์อนุมัติอยู่ในนั้น
5. เปิดลิงก์นั้น → กดอนุมัติ → กลับมาดูชีต สถานะต้องเปลี่ยนเป็น `approved`

ผ่านครบ 5 ข้อแล้วค่อยแจกลิงก์

## การแก้ไขในอนาคต

แก้ `apps-script/server.part.js` หรือ `recommendation.js` แล้วรัน:

```bash
node build-apps-script.js
```

จะได้ `apps-script/Code.gs` ใหม่ → วางทับใน Apps Script → **ทำให้ใช้งานได้ → จัดการการทำให้ใช้งานได้ → ไอคอนดินสอ → เวอร์ชัน: เวอร์ชันใหม่ → ทำให้ใช้งานได้**

ห้ามสร้าง deployment ใหม่ (URL จะเปลี่ยนแล้วต้องแก้ `config.js` ตาม) และห้ามแก้ `Code.gs` ด้วยมือ เพราะมันถูกสร้างจากสองไฟล์นั้นเพื่อรับประกันว่าตรรกะฝั่งเบราว์เซอร์กับเซิร์ฟเวอร์ไม่เพี้ยนจากกัน

## ข้อควรรู้

**ไม่มีการยืนยันตัวตน** — ระบบเชื่อชื่อที่ผู้กรอกพิมพ์มา ใครได้ลิงก์ก็กรอกได้ เหมาะกับการรวบรวมความต้องการภายใน ไม่เหมาะเป็นหลักฐานผูกพันทางกฎหมาย

**ลิงก์อนุมัติคือสิทธิ์ในตัวเอง** — ใครได้ลิงก์ไป (เช่นถูก forward ต่อ) ก็กดอนุมัติได้ ลิงก์มีลายเซ็นกันการเดา/ปลอมแปลงเฉพาะเรื่องการสร้างลิงก์ปลอมเท่านั้น · การกดเปิดลิงก์ยังไม่ถือเป็นการอนุมัติ ต้องกดยืนยันในหน้านั้นอีกครั้ง (กันระบบสแกนอีเมลขององค์กรที่แอบเปิดลิงก์)

**รหัสผ่าน Admin เดียวใช้ร่วมกันทั้งทีม** — ถ้ามีคนออกจากทีมควรเปลี่ยน (แก้ในสคริปต์แล้ว Deploy เวอร์ชันใหม่)
